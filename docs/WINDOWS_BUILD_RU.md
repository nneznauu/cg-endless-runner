# Сборка финального проекта на Windows

Нужны Windows 10/11 x64 и Visual Studio 2022 с компонентами Desktop development with C++, Windows SDK и C++ CMake tools for Windows. Интернет нужен для первой загрузки зависимостей. Python и ручное скачивание GLAD не требуются.

Открой PowerShell в папке с `CMakeLists.txt` и выполни:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-windows.ps1 -Verify -Run
```

`Bypass` действует только для этого процесса PowerShell; постоянная политика системы не меняется. Скрипт находит Visual Studio 2022, запускает CMake, собирает Release x64, выполняет два теста логики и проверку OpenGL. При ошибке он останавливается и показывает причину. После успешных проверок открывается игра. Space или Enter запускает забег.

Собранный файл находится в `build\windows\bin\Release\EndlessRunner.exe`. Рядом располагаются `shaders` и `licenses`. В этой сборке FreeGLUT связан статически, поэтому отдельная `freeglut.dll` не нужна. При переносе готовой программы сохраняй папку целиком; Windows также нужен Microsoft Visual C++ 2015–2022 x64 Runtime, который обычно устанавливается вместе с Visual Studio.

Повторная команда обновляет изменённые исходники и копирует актуальные шейдеры. Существующий `EndlessRunner.sln` остаётся альтернативой для ранее настроенных локальных библиотек. Для переносимой сборки используй скрипт выше.

## Замеры для отчёта

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-windows.ps1 -Verify -Benchmark
```

Результаты сохраняются в отдельной папке `artifacts\performance-ДАТА-ВРЕМЯ`:

- `summary.csv` — медианное время кадра, FPS, число видимых экземпляров и draw calls.
- `samples.csv` — все три повторения ON/OFF.
- `machine-and-method.json` — версия OpenGL, используемый GPU/renderer, драйверы, сборка, commit и хеш EXE, методика.
- `report-table.md` — таблица и описание ограничений для переноса в отчёт.
- `run-N.stdout.txt` и `run-N.stderr.txt` — исходные логи.

Измеряется отрисовка одной и той же стресс-сцены с 1000 препятствиями при 1280×720: 20 кадров прогрева, затем 120 кадров, `glFinish` после каждого кадра. Это время на CPU с ожиданием окончания рендеринга, а не GPU timestamp. Обновление игры, загрузка instance-буфера, HUD и swap не включены. Не выдавай результат за средний FPS полного геймплея; отдельно проверь обычный запуск на лабораторном ПК.

Для другого количества объектов запусти после сборки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\measure-performance.ps1 -Instances 5000
```

В стресс-режиме все N экземпляров отправляются на отрисовку. Они могут частично перекрывать друг друга: столбец `visible` означает количество отправленных экземпляров, а не число полностью видимых объектов. Режим включается в игре клавишей N, M уменьшает количество, B возвращает обычный забег.

## Закреплённые зависимости

| Зависимость | Версия | Источник |
|---|---|---|
| GLAD | 0.1.36, OpenGL 3.3 core | Сгенерированные файлы и лицензия в `third_party/glad` |
| GLM | 1.0.1, commit `0af55ccecd98d4e5a8d1fad7de25ba429d60e863` | Официальный репозиторий g-truc/glm |
| FreeGLUT | 3.4.0, commit `63c0e78d84ecbfcf8accd8bac04404427899053b` | Официальный репозиторий freeglut/freeglut |

Архивы GLM и FreeGLUT проверяются по SHA-256 в `cmake/RunnerDependencies.cmake`. Их исходники и лицензии сохраняются в каталоге сборки. Ошибка загрузки или проверки хеша останавливает настройку.

## Ручная проверка перед сдачей

Проверь Ready, минуту игры, столкновение, Game Over, повторный запуск, рост скорости, паузу, прыжок, T, I, C и стрелки, J/L, изменение размера окна. При default-сцене ориентир — не менее 30 FPS на лабораторном ПК при 1280×720. При падении ниже порога требуется режим пониженного качества. Сверь имена и группу в окне, отчёте и README.
