# Первый запуск

Это начальный прототип твоей части проекта: земля по карте высот, камера и игрок.

1. Распакуй содержимое архива в папку `cg-endless-runner`.
2. Открой `EndlessRunner.sln` в Visual Studio 2022 с установленным компонентом разработки на C++.
3. В верхней панели выбери `Release` и `x64`.
4. Нажми `Ctrl + F5`.

При распаковке сохраняй папки архива: рядом с `EndlessRunner.sln` должны находиться `src` и `shaders`. В исправленной версии пути к исходникам задаются от полного пути проекта. Для совместимости проект также распознаёт вариант, в котором все `.cpp` и `.h` лежат рядом с `.vcxproj`, а файлы шейдеров лежат рядом с ним или в `shaders`.

Проект использует твои установленные GLAD, GLM и FreeGLUT. Новые зависимости скачивать не нужно, если прежние папки сохранились. GLFW для этой версии не используется.

В `Dependencies.props` уже заданы пути из твоего проекта через `$(USERPROFILE)`:

| Настройка | Папка по умолчанию |
| --- | --- |
| GladRoot | `$(USERPROFILE)\Desktop\glad` |
| GlmRoot | `$(USERPROFILE)\Downloads\glm-1.0.3\glm` |
| FreeglutRoot | `$(USERPROFILE)\Downloads\freeglut-3.8.0\freeglut-3.8.0` |
| FreeglutLibDir | `$(FreeglutRoot)\build\lib\Release` |

Если сборка сообщает, что библиотека не найдена, открой `Dependencies.props` и исправь соответствующую папку. `GlmRoot` должен содержать вложенный путь `glm\glm.hpp`. `GladRoot` должен содержать `include\glad\glad.h` и `src\glad.c`.

Если при запуске Windows сообщает, что отсутствует `freeglut.dll`, найди DLL от своей сборки FreeGLUT x64 Release и скопируй её в `bin\Release`, рядом с `EndlessRunner.exe`. Проект делает это автоматически для стандартных папок сборки.

Если видишь `STARTUP WARNING (context/loader)`, это сохранённый флаг от этапа создания контекста/загрузки OpenGL. Он записывается в консоль до работы нашего renderer. Новые ошибки программы не игнорируются: сообщения `OpenGL error during ...` указывают конкретный этап. При таком сообщении пришли весь текст консоли.

## Что проверить в окне

Перед проверкой щёлкни по окну игры. В Windows буквенные команды читаются по кодам клавиш: `A/D`, `P`, `R`, `T`, `C`, `V`, `H`, `J/L` работают при английской и русской раскладке. Удержание переключателя, например `P`, вызывает одно переключение до следующего нажатия. После перехода в другое приложение удержание сбрасывается.

Если в старой версии работали только `Space` и `Esc`, переключи раскладку на `ENG` через `Win + Space` либо обнови проект этим архивом и пересобери его. Чтобы обновить проект на месте, замени `src/main.cpp`, добавь `src/Keyboard.h`, замени `EndlessRunner.vcxproj` и `Dependencies.props`. Затем выбери «Сборка → Пересобрать решение» для `Release | x64`.

- Видна дорога с рельефом и оранжевый игрок.
- `Space` запускает прыжок, после которого игрок приземляется на землю.
- `A` и `D` перемещают игрока вбок; это свободное движение, а не дискретная смена полос.
- `T` делает землю плоской и возвращает рельеф; HUD показывает состояние.
- `C` включает орбитальную камеру. Стрелки вращают её, колесо меняет расстояние.
- `J` и `L` поворачивают направление света. Освещение должно меняться.
- `P` ставит движение на паузу, `R` сбрасывает дистанцию.
- `V` показывает сетку, `H` скрывает/показывает справку, `Esc` закрывает окно.
- При изменении размеров окна пропорции 3D-сцены сохраняются.

После запуска можно сделать первые скриншоты для midterm: обычный вид, вид рельефа с орбитальной камеры и сравнение с `T`.

## Следующий этап

Данияр добавляет препятствия через GPU instancing, их генерацию, столкновения, game over и общую игровую логику. Вместе нужно добавить рост скорости и согласовать остальные пункты финального чеклиста. До этого этапа прототип не является завершённым раннером.

Сверьте написание имён с официальным списком команды: текущий HUD содержит `MUKHAMEJAN / DANIYAR` без фамилии Данияра.
