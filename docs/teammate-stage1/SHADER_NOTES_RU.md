# Для чего устроена эта часть проекта

Наша тема требует землю, высота которой определяется картой высот. Поэтому у земли есть два отдельных элемента: плоская сетка из треугольников и текстура, содержащая значения высоты. Во время отрисовки GPU читает текстуру и поднимает каждую вершину сетки. Это позволяет показать, что поверхность действительно строится по данным карты, и сравнить её с плоской землёй клавишей T.

## Откуда берётся карта высот

`HeightField.cpp` создаёт 128 × 128 числовых значений. Несколько синусов и косинусов делают дорогу волнистой и повышают края. Это воспроизводимая генерация данных, а не сторонний asset. Значения передаются в `glTexImage2D` с форматом `GL_R32F`: в каждом пикселе одно вещественное число.

## Что делает terrain.vert

Вход вершины: два числа, положение X и Z в плоской сетке. Для каждого положения вычисляются координаты текстуры:

```text
u = x / terrainWidth + 0.5
v = (z - scrollPhase) / terrainPeriod
y = heightScale * textureLod(heightMap, vec2(u, v), 0).r
```

Полученная 3D-точка проходит через view и projection. Вершины не получают готовую высоту из CPU: сам vertex shader читает карту. CPU хранит ту же карту, чтобы правильно поставить игрока на видимую поверхность.

Для освещения нужна нормаль. Берём высоты по соседству слева, справа, сзади и спереди:

```text
N = normalize(vec3(hWest - hEast, 2 * normalStep, hBack - hFront))
```

При нулевой амплитуде нормаль направлена вверх. На склонах она наклоняется, поэтому поворот света меняет яркость поверхности.

## Как земля становится бесконечной

Игрок остаётся около Z = 0. Значение scrollPhase увеличивается, и выборка карты сдвигается. GL_REPEAT повторяет карту вдоль Z. После 128 метров scrollPhase возвращается к нулю. Высоты периодические. Дорожная разметка повторяется каждые 8 метров: в 128 метрах ровно 16 таких периодов, поэтому на границе цикла она также совпадает.

Общая дистанция хранится отдельно в double для HUD. В shader передаётся только короткая фаза. Поэтому GPU не работает с огромными мировыми координатами после длительного бега.

## Как игрок соприкасается с землёй

CPU повторяет правила фильтрации текстуры: линейное смешивание четырёх соседних texels, повторение Z и ограничение X. Затем `surfaceHeight` интерполирует высоту внутри именно того треугольника сетки, над которым стоит игрок. Это нужно, потому что между вершинами GPU рисует плоский треугольник, а не непрерывную математическую поверхность.

На земле высота ног обновляется по поверхности. В прыжке скорость по Y уменьшается под действием гравитации. Когда ноги достигают поверхности, игрок становится grounded и снова может прыгнуть.

## Что делают остальные шейдеры

- `player.vert` превращает локальный куб в объект сцены через model matrix. Нормаль преобразуется обратной транспонированной матрицей, чтобы масштабирование по разным осям не испортило освещение.
- `lit.frag` рассчитывает направленное освещение через скалярное произведение нормали и направления к свету, добавляет небольшой блик и ослабляет дальние объекты цветом фона.
- `hud.vert` переводит координаты пикселей в координаты экрана. `hud.frag` задаёт цвет букв. Они рисуют только интерфейс; земля и игрок используют освещение.

## Что уметь показать на защите

1. Нажать T: рельеф исчезает и появляется. Объяснить, почему heightScale = 0 даёт плоскость.
2. Нажать C и повернуть камеру: показать настоящую форму поверхности.
3. Нажать J или L: показать изменение освещения склонов.
4. Нажать V: показать сетку, вершины которой сдвигает shader.
5. Изменить amplitude в HeightField.h и пересобрать: высота меняется одновременно для GPU и контакта игрока с землёй.
6. Найти textureLod и объяснить, какие входные данные превращаются в высоту.

Для отчёта укажите AI assistance и опишите свои изменения после изучения исходного прототипа. GPU instancing пока не реализован и должен быть отмечен как pending.
