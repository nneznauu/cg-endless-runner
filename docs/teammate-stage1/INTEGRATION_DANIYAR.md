# Согласование с модулем препятствий

Текущая часть отвечает за землю, игрока, камеру и базовую отрисовку. Данияр добавляет собственный модуль препятствий и инстансный vertex shader.

## Координаты и движение

- Y направлена вверх.
- Игрок находится около Z = 0, камера позади него в положительном Z.
- Впереди игрока находится отрицательное Z. Препятствия появляются впереди, затем движутся в сторону положительного Z.
- Текущая скорость мира: 8 метров в секунду. При интеграции вынесите скорость в общий GameState.
- X игрока ограничен диапазоном [-4.2, 4.2]; текущий игрок движется свободно, без привязки к полосам.
- Размер игрока: 0.8 × 1.2 × 0.8. `player.feetY` задаёт низ его collider.
- Высоту препятствия на земле определяйте через `terrain.surfaceHeight(x, z, phase, displaced)`.

При перемещении препятствия учитывайте высоту земли в его текущем локальном положении. Для обычного куба центр по Y будет `groundHeight + cubeHeight / 2`.

## Требование instancing

Положения всех препятствий одного типа должны храниться в instance buffer. Атрибуты экземпляра получают divisor = 1. Один тип препятствия рисуется одним `glDrawElementsInstanced`, а не циклом из отдельных draw calls.

Матрица каждого экземпляра может занимать четыре последовательных атрибута. У обычного меша можно использовать location 0 для положения и location 1 для нормали; для instance matrix тогда удобны locations 2–5.

Добавьте отдельный переключатель instancing для сравнения с обычной отрисовкой тех же препятствий. При выключении препятствия должны остаться на месте; меняется способ отрисовки.

## Точки подключения

- `src/main.cpp`: игровой update и обработка столкновений/состояний игры.
- `src/Renderer.cpp`: отрисовка препятствий после земли и перед HUD.
- `Camera::view()`: матрица view; perspective рассчитывается в Renderer::draw.
- `statusText()`: добавить Game Over, restart и состояние instancing.
- `R`: текущий reset должен также сбрасывать препятствия и game state.
- `P`: препятствия должны останавливаться вместе с остальным миром.

Для загрузки собственных шейдеров используйте `loadProgram` из Shader.cpp. Каждый член команды должен понимать обе графические технологии к финальной защите.

В отчёте отражайте реально выполненные модули. Следующие функции остаются общими этапами: рост скорости, полноценная проверка препятствий, start/game-over/restart, таблица FPS и резервное видео.
